# Historical battlefield scenarios

The map picker has two collections: eight World Campaigns and five Historical
Battles. Existing preset IDs, saved campaigns and world-campaign rules remain
compatible.

## Scope and historical interpretation

These are **topographic historical reconstructions**. The north-up frames use
measured elevation from pinned Mapzen Terrain Tiles: EU-DEM for Waterloo,
Environment Agency LiDAR/EU-DEM for Hastings, SRTM for Sekigahara and Hattin, and USGS NED for Gettysburg.
See the shipped [source and attribution page](../ui/maps/battle-sources.html).

Shaded relief and 10 m / 25 m contours are derived from the elevation raster.
Contours and elevations are in metres relative to sea level. Shading exaggerates
low relief for legibility without changing contour values. We interpolate over
the post-1815 Lion's Mound and repair invalid Hattin samples from neighbouring
valid data. Other modern earthworks can remain in the baseline. Hattin's lake
edge follows the DEM water surface; this is not a surveyed 1187 shoreline.

Forests, orchards, fields, watercourses, roads and strongpoint symbols are
original historical landscape reconstructions. Their exact outlines are
interpretations, not claimed cadastral records. No current urban street network,
railways or modern building layer is included. Sekigahara landmark locations were
corrected using the CCL Ogaki branch's CC BY 3.0 location dataset, credited on the
source page. Other tactical anchors remain approximate.

Sector boundaries are generated by a seeded watershed over terrain slope and
simplified with shared-edge topology preserved. They follow local relief instead
of straight Voronoi edges; they are still gameplay boundaries, not historical
borders. Movement routes come from shared edges and reconstructed stream crossings.
Each region's fixed terrain class remains the gameplay modifier shown on hover;
the detailed background shows variation within a sector.

Starting armies are scaled game strengths, not historical head counts. Terrain
uses the existing six types: `city` means a fortified settlement or strongpoint;
`hills` means defensible elevated ground. Standard terrain and supply modifiers
apply. There are no artillery, cavalry, morale, thirst, defection or timed
reinforcement systems in this version. Sources and scenario assumptions are
available in each map's briefing.

## Rules

- Each battlefield has two fixed starting sides. Selecting the other side swaps
  ownership and headquarters while preserving forces, objectives and terrain.
- All sectors start under one side's control; no randomly placed neutral militia.
- Army strength does not grow, including in isolated or captured sectors.
- Three gold diamond markers identify objectives. After turn 20, more objectives
  wins; ties use surviving strength, then the scenario's historical defender.
  Waterloo/Hastings/Sekigahara/Gettysburg favor the initial defending side on an exact tie;
  Hattin favors the Ayyubid side. This is a game rule, not a historical claim.
- Eliminating the other side's forces or territory ends the battle early.
- Crown markers are supply headquarters; losing one does not itself end a battle.
- The AI values objectives and advances reserves toward contested objectives.
- Rules and side identities are persisted with the campaign, so reload and replay
  retain the chosen side. Existing saves default to normal recruitment/no battle
  metadata.

## Authoring and rebuilding

Edit `engine/presets/battles/__init__.py` for frames, anchors, terrain classes, forces,
objectives, sources and context. IDs are stable within each scenario: do not
reorder deployed sectors without a save/atlas migration.

```sh
.venv/bin/python -m pip install -r games/imperium/tools/requirements-battle-maps.txt
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m games.imperium.tools.build_battle_maps
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m games.imperium.tools.build_thumbnails
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m unittest discover -s games/imperium/tests -q
NODE_PATH=/path/to/node_modules node games/imperium/tools/check_historical_battles.cjs
```

Install the build-only dependencies in `requirements-battle-maps.txt`. It writes the browser atlas, shared-border movement
routes and thumbnail assets; it never runs on a game request. The Natural Earth
strategy builder skips these maps. Browser checks default to the combined local
preview at port 3000; set `IMPERIUM_TEST_URL` and `IMPERIUM_TEST_API` if separate.

## Source pinning and performance

`tools/battle_sources/*-elevation.npz` are clipped, reprojected source rasters.
Companion JSON manifests record every source tile URL, SHA-256 and source-dataset
header. Builds use these committed inputs and do not require network access.
To deliberately refresh the input data, run `python -m
games.imperium.tools.fetch_battle_terrain`. Curl uses the host trust store and
caches raw tiles under the system temporary directory.

`battle_sources/landscape.py` contains interpreted vegetation, paths and streams.
`battle_terrain.py` produces relief imagery, contours and connected sectors.
The five 1536-pixel-wide WebP terrain images are compressed for browser delivery. The browser
loads one image per battle, with ownership drawn as a light overlay, and reuses
the existing bounded terrain canvas cache. Pointer movement does not repaint
the relief. Thumbnails embed reduced versions of the actual terrain artwork.
